## Модель Split–Apply–Combine

Группировка выполняется в три этапа:

1. **Split** — строки разделяются на группы. В уроке станки разделялись по
   `is_running` на работающие и остановленные.
2. **Apply** — к каждой группе применяется вычисление, например среднее,
   максимум или подсчёт строк.
3. **Combine** — результаты групп собираются в общую сводку.

Фильтрация отвечает на вопрос «какие строки подходят?», а группировка — «какие
группы существуют и каковы показатели каждой группы?».

## Простая агрегация

```python
mean_temperature_by_status = (
    readings.groupby("is_running")["temperature"].mean()
)
```

Получен `Series` формы `(2,)`. Значения `False` и `True` стали индексом, а
средние температуры — значениями `Series`.

При `as_index=False` ключ группировки остаётся обычным столбцом:

```python
mean_temperature_table_by_status = (
    readings.groupby("is_running", as_index=False)["temperature"].mean()
)
```

Результат — `DataFrame` формы `(2, 2)` со столбцами `is_running` и
`temperature`.

## Размер групп и максимальные обороты

```python
machine_count_by_status = readings.groupby("is_running").size()
max_rpm_by_status = readings.groupby("is_running")["rpm"].max()
```

Для текущих данных:

```text
False → 1 строка, max rpm = 0
True  → 3 строки, max rpm = 1420
```

## Именованная агрегация

Один инженерный отчёт построен через `agg()`:

```python
status_summary = readings.groupby("is_running", as_index=False).agg(
    machine_count=("machine_id", "size"),
    mean_temperature=("temperature", "mean"),
    max_rpm=("rpm", "max"),
)
```

В конструкции:

```python
mean_temperature=("temperature", "mean")
```

- `mean_temperature` — имя нового столбца;
- `temperature` — исходный столбец;
- `mean` — операция над каждой группой.

Форма отчёта — `(2, 4)`.

## size и count при пропусках

Создана независимая копия таблицы:

```python
readings_with_missing = readings.copy()
readings_with_missing.loc[1, "temperature"] = pd.NA
```

`.copy()` защитил исходный `readings` от изменения. Для работающих станков:

```text
size  = 3 — все строки группы;
count = 2 — строки с непустой temperature.
```

`.size()` отвечает на вопрос «сколько записей получено?», а `.count()` — «в
скольких записях конкретное измерение присутствует?».

## Отчёт качества данных

```python
quality_summary = readings_with_missing.groupby(
    "is_running",
    as_index=False,
).agg(
    machine_count=("machine_id", "size"),
    temperature_count=("temperature", "count"),
    mean_temperature=("temperature", "mean"),
)

quality_summary["missing_temperature_count"] = (
    quality_summary["machine_count"]
    - quality_summary["temperature_count"]
)
```

Для группы `True` получен один пропуск. Среднее осталось `72.0`, потому что
pandas пропустил `NaN` и усреднил `68.5` и `75.5`. Совпадение со старым средним
показало важный риск: агрегат может не измениться, хотя качество данных стало
хуже.

Для полного отображения широкой таблицы использовано:

```python
print(quality_summary.to_string(index=False))
```

## Инженерные ограничения

- Среднее по одной записи математически корректно, но статистически слабо.
- Среднее нельзя оценивать без размера группы и числа фактических измерений.
- Пропуски могут быть сбоем датчика, передачи или преобразования, но допустимость
  определяется контрактом данных.
- Усреднение параметров с разным физическим смыслом не имеет инженерной ценности.

## Ошибки и уточнения

- Печатный результат группировки сначала был принят за `DataFrame (2, 2)`.
  Проверка показала `Series (2,)`: ключ группировки находился в индексе.
- Исходный столбец именованной агрегации был принят за ключ группировки.
  Уточнено: ключ задаётся в `groupby()`, а кортеж содержит исходный столбец и
  операцию.
- Сокращение столбцов через `...` в терминале было принято за отсутствие данных.
  Это только формат отображения; `to_string()` показал все столбцы.
- Длинные выражения приведены к многострочному формату PEP 8.
