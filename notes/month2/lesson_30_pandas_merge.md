# Урок 30 — объединение таблиц через merge

Дата завершения: 2026-08-12.

## Цель урока

Научиться объединять измерения со справочными данными по общему ключу и
проверять, что соединение не теряет и не размножает строки незаметно.

После урока пользователь умеет:

- определять левую и правую таблицы;
- выбирать ключ соединения;
- различать `inner` и `left merge`;
- диагностировать несовпавшие ключи через `indicator=True`;
- проверять ожидаемую связь через `validate="many_to_one"`;
- объяснять размножение строк при дублирующихся ключах;
- формировать отчёт по отсутствующим справочным данным.

## Входные таблицы

Левая таблица `readings` содержит измерения четырёх станков. Правая таблица
`machine_catalog` является справочником модели и цеха:

```text
readings:        CNC-01, CNC-02, CNC-03, CNC-04
machine_catalog: CNC-01, CNC-02, CNC-03, CNC-05
```

Общий ключ соединения — `machine_id`.

## Inner merge

```python
inner_result = readings.merge(
    machine_catalog,
    on="machine_id",
    how="inner",
)
```

`inner` сохраняет только ключи, присутствующие в обеих таблицах: `CNC-01`,
`CNC-02`, `CNC-03`. `CNC-04` отсутствует в справочнике, а `CNC-05` — в
измерениях. Результат имеет форму `(3, 6)`.

## Left merge

```python
left_result = readings.merge(
    machine_catalog,
    on="machine_id",
    how="left",
    indicator=True,
    validate="many_to_one",
)
```

`left` сохраняет все четыре измерения. Для `CNC-04` значения `model` и
`workshop` стали `NaN`, потому что соответствие справа не найдено. Для сценария,
где нельзя терять фактически полученные измерения, `left` безопаснее `inner`.

## Индикатор происхождения

`indicator=True` добавил столбец `_merge`:

- `both` — ключ найден в обеих таблицах;
- `left_only` — ключ найден только слева;
- `right_only` — ключ найден только справа.

Диагностический отчёт:

```python
missing_catalog_report = left_result.loc[
    left_result["_merge"] == "left_only",
    ["machine_id", "temperature", "_merge"],
]
```

В результате получена одна строка `CNC-04`, форма `(1, 3)`.

## Проверка отношения ключей

`validate="many_to_one"` задаёт ожидаемый контракт:

- слева один станок может иметь много измерений;
- справа каждому станку должна соответствовать одна справочная строка.

`validate` не удаляет дубли. При нарушении контракта он останавливает соединение
с ошибкой, предотвращая незаметное размножение записей.

## Почему дубли размножают строки

Для одного ключа число строк результата равно:

```text
число строк слева × число совпадений справа
```

Если слева две строки `CNC-01`, а справа три, соединение создаст шесть строк с
этим ключом. Каждая левая строка соединяется с каждой подходящей правой строкой.

## Инженерные ограничения

- Неверный `how` может незаметно удалить измерения.
- Несовпавшие ключи нужно выводить в отдельный диагностический отчёт.
- Дубли ключей могут исказить количество, средние и суммы.
- Перед соединением нужно проверять названия и типы ключевых столбцов.
- После соединения нужно проверять число строк, `_merge` и ожидаемое отношение
  ключей.

## Ошибки и уточнения

- Сначала ожидалось, что `inner` сохранит `CNC-01`–`CNC-04`. Исправлено: `inner`
  сохраняет только пересечение ключей.
- `left merge` был описан как перенос ключей во вторую таблицу. Уточнено: обе
  исходные таблицы не изменяются, создаётся новый результат.
- Для одной строки слева и двух совпадений справа ожидалось три строки.
  Исправлено: получается `1 × 2 = 2`.
- Для двух строк слева и трёх справа ожидалось две строки. Исправлено:
  получается `2 × 3 = 6`.
- `validate` сначала был описан как предотвращение дублей. Уточнено: он проверяет
  контракт и выдаёт ошибку, но не исправляет данные.

## Math Core

Соединение связано с операциями над множествами ключей:

```text
left:  A, B, C, D
right: A, B, C, E
inner → 3 ключа
left  → 4 строки
outer → 5 разных ключей
```

При дублировании применяется правило произведения количества совпадений.

## English Core — долг на запись/повторение

- **merge** — объединение таблиц;
- **join key** — ключ соединения;
- **match** — совпадение;
- **left table** — левая, основная таблица;
- **duplicate key** — дублирующийся ключ;
- **many-to-one** — связь «многие к одному».

Фраза: **Keep every measurement and report unmatched machine identifiers** —
«Сохрани каждое измерение и сообщи об идентификаторах станков, для которых нет
соответствия».

## Anki — долг

1. **Когда выбирать `left merge` вместо `inner merge`?** — Когда необходимо
   сохранить все строки основной левой таблицы и увидеть отсутствующие
   совпадения как `NaN`.
2. **Зачем использовать `indicator=True` и `validate`?** — `indicator`
   показывает происхождение строк, а `validate` проверяет ожидаемый тип связи.
3. **Почему дубли ключей увеличивают результат `merge`?** — Для каждого ключа
   число строк результата равно числу строк слева, умноженному на число
   совпадений справа.

`left merge`, построил диагностический отчёт, применил `indicator` и `validate`,
