# Урок 20 — виртуальное окружение и зависимости

Дата: 2026-07-24
Артефакт: [requirements.txt](../../requirements.txt)
Статус: `Practiced`; требуется отсроченное воспроизведение в следующей сессии.

## Цель

Создать изолированную Python-среду проекта, установить зависимость в правильный
интерпретатор и сохранить воспроизводимый список версий.

## Теория

**Интерпретатор** выполняет Python-код. На одном компьютере могут существовать
несколько интерпретаторов и несколько независимых наборов пакетов.

**Пакет** — сторонний программный компонент, например NumPy. Если проект не
работает без пакета, пакет является его **зависимостью**.

**Виртуальное окружение** `.venv` содержит отдельный Python, отдельный pip и
отдельный каталог `site-packages`. Оно предотвращает конфликты версий между
проектами.

Команда `python -m pip` означает: запустить модуль pip именно тем
интерпретатором, который указан словом `python`. Это надёжнее отдельной команды
`pip`, когда на компьютере установлено несколько Python.

## Выполненный workflow

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install numpy
python -m pip freeze
python -m pip install -r requirements.txt
```

После активации путь `python -m pip --version` указал на
`.venv\Lib\site-packages`, что фактически подтвердило выбор среды.

## Активация и прямой вызов

Активация временно ставит `.venv\Scripts` в начало `PATH`. Она не создаёт
изоляцию, а только упрощает выбор уже созданного интерпретатора.

Окружение можно использовать без активации:

```powershell
.\.venv\Scripts\python.exe -m pip --version
```

## Фиксация зависимостей

`requirements.txt` хранит воспроизводимый рецепт:

```text
numpy==2.5.1
```

`==` требует точную версию. Даже более новая версия не удовлетворяет такому
ограничению. Ключ `-r` заставляет pip прочитать требования из файла.

`.venv` не публикуется: это большой автоматически создаваемый и
платформозависимый каталог. `requirements.txt` публикуется, потому что по нему
другой разработчик или CI может восстановить среду.

## Windows и кодировка

Оператор PowerShell `>` создал `requirements.txt` в UTF-16 LE. Это обнаружено
по байтам `FF FE`. Файл был перезаписан в UTF-8:

```powershell
python -m pip freeze | Set-Content -Encoding utf8 requirements.txt
```

Байты `EF BB BF` подтвердили UTF-8 BOM. Явная кодировка уменьшает расхождения
между Windows, Linux, Docker и CI.

## Инженерное задание

Сформирован минимальный воспроизводимый слой проекта: окружение не попадает в
Git, а точная зависимость хранится в репозитории и устанавливается одной
командой.

## Ошибки и корректировки

- Причиной скрытия `.venv` сначала называлось отсутствие обновления Git;
  уточнено, что Git автоматически применяет `.gitignore`.
- `.venv` сначала предлагалось создать как обычную папку; для рабочей среды
  необходим `python -m venv .venv`.
- Команда создания окружения была восстановлена с одной подсказкой по флагу
  `-m`.
- Выполненное требование объяснялось «последней версией»; реальная причина —
  совпадение с точным ограничением `numpy==2.5.1`.
- Обнаружена и исправлена системная кодировка UTF-16.

## Math Core

Точная зависимость задаёт равенство версии: установленная версия должна
совпасть с требуемой. Версию удобно воспринимать как упорядоченную тройку
`(major, minor, patch)`, но запись `==` не допускает замену даже на более новую
тройку.

## English Core

- **interpreter** — интерпретатор, программа выполнения Python-кода;
- **package** — пакет;
- **dependency** — зависимость проекта;
- **virtual environment** — виртуальное окружение;
- **activate** — активировать;
- **requirements file** — файл требований;
- **alias** — псевдоним;
- **reproducibility** — воспроизводимость.

## Anki

1. **Почему использовать `python -m pip`, а не просто `pip`?** — Так pip
   запускается конкретным выбранным интерпретатором Python.
2. **Почему `.venv` игнорируется, а `requirements.txt` хранится в Git?** —
   Окружение генерируется заново, а файл требований является рецептом его
   воспроизведения.
3. **Как восстановить среду проекта на Windows?** — Создать `.venv`,
   активировать её и выполнить `python -m pip install -r requirements.txt`.
