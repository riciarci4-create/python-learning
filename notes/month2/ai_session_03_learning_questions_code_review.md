# AI-сессия 3 — инженерные вопросы, проверка ответов и code review

## Цель сессии

Научиться использовать LLM как помощника, а не как источник истины:

- задавать воспроизводимые инженерные вопросы;
- заранее определять контракт и ожидаемое поведение;
- проверять утверждения через документацию, минимальный код и тесты;
- отличать содержательный code review от общего одобрения;
- не применять изменения AI без проверки и явного решения инженера.

## Почему уверенный ответ AI может быть неверным

LLM формирует вероятное продолжение текста. Уверенный стиль ответа не является
доказательством корректности. Проверка строится по цепочке:

1. понять утверждение и определить, что именно можно проверить;
2. свериться с официальной документацией нужной версии;
3. создать минимальный воспроизводимый пример;
4. запустить его в зафиксированной среде;
5. сравнить ожидаемый и фактический результаты;
6. закрепить критичное поведение тестом.

## Структура инженерного вопроса

Хороший запрос содержит:

- контекст задачи;
- версии языка и библиотек;
- код или точный путь к нему;
- контракт функции;
- входные данные;
- ожидаемый и фактический результаты;
- уже выполненные проверки;
- ограничение на форму помощи, например «минимальная подсказка» или «не изменяй
  код без команды».

Для `calculate_z_score()` контракт был сформулирован так:

> Нормальная база возвращает числовой z-score, пустая и постоянная базы
> возвращают `None`.

Нормальная база — основной сценарий (**happy path**), а пустая и постоянная
базы — крайние случаи (**edge cases**).

## Минимальный эксперимент с пустым NumPy-массивом

Проверялось утверждение AI:

> `np.mean()` для пустого массива вызывает `ValueError`.

В среде Python 3.13 и NumPy 2.5.1 эксперимент показал:

- результат вычисления — `nan`;
- NumPy вывел два `RuntimeWarning`;
- `ValueError` не возник;
- процесс завершился с кодом `0`.

Следовательно, предупреждение не равно исключению. `RuntimeWarning` сообщает о
проблемном вычислении, но не останавливает программу. Возвращённый `nan` может
распространяться по дальнейшим вычислениям, поэтому пустой массив нужно проверять
до вычисления среднего.

## Ошибка «метод вместо результата»

В первой версии эксперимента было записано:

```python
test_mean = test.mean
```

Это сохранило ссылку на метод. Вызов со скобками `test.mean()` выполняет метод и
возвращает результат. Вывод вида `<built-in method mean ...>` является признаком,
что метод не был вызван.

## Проверяемый code review

Фраза «код хороший, всё работает» не является полноценным review. Проверка
должна охватывать как минимум:

- **correctness** — соответствует ли результат контракту;
- **edge cases** — что происходит на границах допустимых входов;
- **readability** — понятны ли имена и структура;
- **maintainability** — удобно ли безопасно изменять код;
- **architecture** — правильно ли разделена ответственность;
- **security** — нет ли актуальных рисков для данного кода;
- **reproducibility** — можно ли повторить проверку в той же среде;
- **tests** — какие сценарии запускались и каковы результаты.

Отчёт должен содержать наблюдаемые доказательства: версию среды, входы,
ожидаемые результаты, фактические результаты и команды проверки. Рекомендации AI
не применяются автоматически.

## Test oracle

**Test oracle — критерий ожидаемого результата теста.** Его определяют до
проверки реализации. Для функции z-score:

- пустая база → `None`;
- постоянная база с `std == 0` → `None`;
- нормальная база с ненулевым разбросом → числовой z-score.

Без заранее определённого результата тест может только запустить код, но не
доказать его корректность.

## Практика сессии

- Составлен инженерный запрос на review `calculate_z_score()` с версиями среды,
  контрактом, сценариями и запретом изменять функцию без команды.
- Экспериментально опровергнуто неверное утверждение о `ValueError`.
- Результат сформулирован как воспроизводимое доказательство, а не как «всё
  работает».
- Выделены признаки слабого code review: отсутствие крайних случаев, проверки
  структуры, повторного запуска и отчёта о тестах.

## Math Core

Повторена математическая причина защиты постоянной базы: если все значения
одинаковы, стандартное отклонение равно нулю, а формула z-score требует деления
на стандартное отклонение. Поэтому z-score не определён, а `None` является
выбранным контрактом программы.

## English Core

- **evidence** — доказательство;
- **reproducible evidence** — воспроизводимое доказательство;
- **happy path** — основной успешный сценарий;
- **edge case** — крайний случай;
- **test oracle** — заранее определённый ожидаемый результат теста;
- **code review** — систематическая проверка кода;
- **correctness** — соответствие результата требованиям;
- **side effect** — побочный эффект выполнения.

## Критерии усвоения

Сессия усвоена на уровне `Practiced`, если пользователь:

- формулирует вопрос с контекстом, средой и контрактом;
- не принимает уверенность AI за доказательство;
- проверяет ответ документацией, кодом и тестами;
- различает предупреждение, исключение и возвращённое значение;
- требует от code review проверяемые доказательства;
- запрещает AI изменять код без явной команды.

Для уровня `Retained` нужно в следующей AI-сессии воспроизвести цепочку проверки
без конспекта.
