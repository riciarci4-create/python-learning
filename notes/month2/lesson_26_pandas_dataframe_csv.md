## DataFrame и Series

`DataFrame` — двумерная подписанная таблица. У неё есть:

- `columns` — названия столбцов;
- `index` — метки строк;
- `values` — значения;
- `dtypes` — тип каждого столбца;
- `shape` — пара `(количество строк, количество столбцов)`.

`Series` — одномерная подписанная последовательность. Один выбранный столбец
`DataFrame` обычно возвращается как `Series`.

В отличие от обычного NumPy-массива, разные столбцы `DataFrame` могут иметь
разные типы: идентификатор — строковый, температура — дробный, обороты — целый,
состояние — логический.

## Создание DataFrame из словаря

Словарь производственных данных преобразован в таблицу:

```python
machine_data = {
    "machine_id": [1, 2, 3],
    "temperature": [70, 71, 72],
    "rpm": [1000, 1100, 1200],
    "is_running": [True, False, True],
}

table = pd.DataFrame(machine_data)
```

Ключи словаря становятся столбцами, а элементы с одинаковыми позициями образуют
строки. Все списки должны иметь одинаковую длину. Полученная форма — `(3, 4)`:
три станка и четыре признака.

Первоначально состояние было записано строками `"Yes"` и `"No"`. Для
внутренней модели данных лучше использовать `True` и `False`: pandas назначает
тип `bool`, фильтрация становится однозначной, а разные написания текста не
создают лишние состояния. `0/1` допустимы на границе с оборудованием, но внутри
программы их полезно преобразовывать в `bool`.

## Определение типов

pandas определяет тип по фактическим значениям, а не по названию столбца:

```text
machine_id     int64
temperature    int64
rpm            int64
is_running      bool
```

Температуры `70`, `71`, `72` являются целыми, поэтому столбец получил `int64`.
Если в столбце присутствуют значения вроде `70.5`, он получает дробный тип.

Строка `dtype: object` внизу вывода `table.dtypes` относится к служебной
`Series`, содержащей описания разных типов, а не ко всем данным таблицы.

## Выбор столбца

```python
temperatures = table["temperature"]
```

Результат имеет тип `pandas.Series` и форму `(3,)`. Запятая в `(3,)` показывает,
что это форма одномерной последовательности, а не просто число в скобках.

## CSV и автоматическое определение типов

CSV — **Comma-Separated Values**, текстовые значения, разделённые запятыми.
Первая строка обычно является `header`, остальные — `records`.

Создан файл `machine_readings.csv` с четырьмя строками. После чтения:

```python
readings = pd.read_csv(csv_path)
```

получена форма `(4, 4)` и типы:

```text
machine_id         str
temperature    float64
rpm              int64
is_running        bool
```

Это **type inference** — pandas предполагает тип по содержимому. Автоматический
вывод нужно проверять: идентификаторы, даты, пропуски и повреждённые значения
могут быть интерпретированы неверно.

## Надёжный путь к CSV

CSV лежит рядом с `lesson26.py`, поэтому путь строится от папки текущего файла:

```python
lesson_dir = Path(__file__).resolve().parent
csv_path = lesson_dir / "machine_readings.csv"
```

`Path(__file__).resolve()` указывает на сам Python-файл. Один `.parent` даёт
`week6`. Три `.parent` подняли бы путь до корня проекта, где CSV отсутствует.
Без `.parent` Python попытался бы трактовать `lesson26.py` как каталог.

Код проверен запуском из корня проекта и из другой рабочей директории.

## Базовая проверка схемы

Ожидаемая схема задаётся инженером:

```python
expected_columns = ["machine_id", "temperature", "rpm", "is_running"]
actual_columns = readings.columns.tolist()
columns_are_valid = actual_columns == expected_columns
not_readings_empty = not readings.empty
```

Сравнение списков проверяет длину, значения и порядок столбцов. Свойство
`readings.empty` отвечает на вопрос «таблица пустая?». Оператор `not` меняет
вопрос на «таблица содержит строки?». Обе проверки вернули `True`.

Это только первая граница качества. В следующих уроках появятся проверки
пропусков, диапазонов и дубликатов.

## Инженерная интерпретация

Строка `CNC-03` требует внимания:

- `temperature = 91.5`;
- `rpm = 0`;
- `is_running = False`.

Сочетание может означать перегрев после остановки, аварийное отключение или
ошибку датчика. Данные показывают подозрительный сигнал, но сами по себе не
доказывают причину.

## Ошибки и причины

- Форма была предсказана как `(4, 3)`, хотя `shape` хранит сначала строки, затем
  столбцы. Для трёх станков и четырёх признаков правильно `(3, 4)`.
- Температуре был предсказан `float`, но все исходные значения были целыми;
  pandas смотрит на фактические данные.
- `pd.read.csv` разбирается как поиск атрибута `read`, которого нет. Имя функции
  является единым идентификатором `read_csv`.
- Три `.parent` привели к корню проекта вместо папки CSV.
- Путь без `.parent` пытался присоединить CSV к имени Python-файла.
- `not_readings_empty = readings.empty` сохранило ответ на противоположный
  вопрос. Для проверки наличия строк нужен `not readings.empty`.

## Math Core

- `shape = (rows, columns)` описывает размерность таблицы.
- Выбор одного столбца уменьшает размерность с двумерной `(n, m)` до одномерной
  `(n,)`.
- Схему можно рассматривать как упорядоченный набор признаков: изменение порядка
  или количества столбцов изменяет контракт входного вектора данных.
