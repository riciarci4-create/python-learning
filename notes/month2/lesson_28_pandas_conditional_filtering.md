## Цель урока

Научиться строить булевы маски по одному или нескольким условиям и применять их
к `DataFrame`, чтобы получать воспроизводимые инженерные отчёты.

После урока пользователь умеет:

- создавать маску сравнением столбца с порогом;
- объяснять поэлементную природу сравнения `Series`;
- фильтровать все столбцы таблицы готовой маской;
- одновременно выбирать строки и столбцы через `loc`;
- объединять условия операторами `&`, `|`, `~`;
- учитывать различие между `>` и `>=` на границе;
- распознавать корректный пустой `DataFrame`;
- проверять пустой результат через `.empty` и `shape`.

## Булева маска

Сравнение столбца с порогом выполняется поэлементно:

```python
high_temperature_mask = readings["temperature"] >= 85
```

Результат — `Series` с одним булевым значением на каждую исходную строку.
`True` означает «выбрать строку», `False` — «не выбирать». Индекс маски связан с
индексом исходной таблицы.

Для текущего CSV получена маска:

```text
False, False, True, False
```

## Применение маски

Выбор всех столбцов подходящих строк:

```python
high_temperature_machines = readings[high_temperature_mask]
```

Получен `DataFrame` формы `(1, 4)`. Исходный индекс `2` сохранён. Это поддерживает
прослеживаемость: можно установить, из какой исходной записи получен результат.

Выбор строк и только нужных столбцов:

```python
high_temperature_report = readings.loc[
    high_temperature_mask,
    ["machine_id", "temperature"],
]
```

Результат имеет форму `(1, 2)`. До запятой в `loc` передаётся средство выбора
строк, после запятой — метки столбцов.

## Составные условия

Операторы pandas работают поэлементно:

- `&` — логическое И: оба условия должны быть истинны;
- `|` — логическое ИЛИ: достаточно одного истинного условия;
- `~` — логическое НЕ: инвертирует каждое булево значение.

Пример И:

```python
warm_running_mask = (
    (readings["temperature"] >= 75)
    & readings["is_running"]
)
```

Пример ИЛИ и НЕ:

```python
attention_mask = (
    (readings["temperature"] < 70)
    | (~readings["is_running"])
)
```

Сравнения заключаются в скобки, чтобы границы каждого условия и порядок
вычислений были явными. `and`, `or`, `not` не заменяют здесь `&`, `|`, `~`, потому
что необходимо обработать целую `Series`, а не одно булево значение.

## Почему список вокруг маски сломал loc

Рабочая форма:

```python
readings.loc[high_temperature_mask, ["machine_id", "temperature"]]
```

Ошибочная форма:

```python
readings.loc[[high_temperature_mask], ["machine_id", "temperature"]]
```

`high_temperature_mask` уже является одномерной маской. Дополнительные скобки
создают список, содержащий целую `Series`, то есть вложенную структуру. pandas
перестаёт воспринимать её как плоскую булеву маску и пытается найти содержимое
как метку строки, поэтому возникает `KeyError`.

Список столбцов корректен, потому что это плоский список отдельных меток:
`["machine_id", "temperature"]`.

## Пустой результат

Условие `temperature > 100` дало маску из четырёх `False`. После выбора двух
столбцов результат имеет форму `(0, 2)`:

- `0` строк;
- `2` столбца.

Это корректный `DataFrame`, а не ошибка. Проверка:

```python
no_match_report.empty
```

возвращает `True`. Перед агрегированием, формированием предупреждений или
передачей результата дальше пустой отчёт необходимо обрабатывать явно.

## Инженерное задание

Сформирован отчёт о станках, требующих внимания. Станок включается в него, если:

1. температура не ниже `85`; или
2. станок работает, но обороты ниже `1300`.

```python
requires_attention_mask = (
    (readings["temperature"] >= 85)
    | (readings["is_running"] & (readings["rpm"] < 1300))
)
```

В отчёт вошли `CNC-01` и `CNC-03`, форма результата — `(2, 4)`.

## Граничное условие

Первоначально в инженерной маске было написано `temperature > 85`, хотя контракт
требовал «не ниже 85». На текущих данных ошибка не проявилась, потому что
температуры ровно `85.0` не было. Оператор исправлен на `>=`, чтобы реализация
соответствовала требованию на границе.

## Ошибки и исправленные модели понимания

- При первом прогнозе `A & B` для горячего, но выключенного станка ожидалось
  `True`; исправлено: `True & False` даёт `False`.
- Действие `~` сначала было понято как изменение уже выбранных строк. Уточнено:
  сначала инвертируется исходная булева `Series`, затем `loc` выбирает значения
  `True` новой маски.
- Результат фильтрации был описан как «не новая таблица». Уточнено: получается
  отдельный `DataFrame`, сохраняющий исходные метки индекса.
- Для пустого результата ожидалась форма `(2,)`. Уточнено: выбор списка из двух
  столбцов сохраняет двумерность, поэтому форма равна `(0, 2)`.
- Дополнительный список вокруг готовой маски вызвал `KeyError`; причина
  диагностирована через различие плоской маски и вложенной структуры.

## Math Core

Урок связан с булевой алгеброй:

```text
True & False = False
True | False = True
~False       = True
```

Составная маска — поэлементное логическое выражение. Скобки отражают структуру
инженерного правила. Различие `>` и `>=` определяет принадлежность граничного
значения множеству допустимых или опасных значений.

## English Core

- **boolean mask** — булева маска, средство выбора строк через `True/False`;
- **condition** — условие, проверяемое для каждой строки;
- **filtering** — фильтрация, отбор данных по условию;
- **boundary case** — граничный случай, значение на границе правила;
- **traceability** — прослеживаемость, возможность определить происхождение
  выбранной записи;
- **refactoring** — рефакторинг, улучшение структуры без изменения поведения.

Фраза урока: **Filter the rows where the condition is true** — «Отфильтруй
строки, для которых условие истинно».
